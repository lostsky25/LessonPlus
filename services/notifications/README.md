# notifications

Сервис получает `SubscriptionActivated` из quorum-очереди `lessonplus.notifications.events`, привязанной к topic-обменнику `lessonplus.events` по одноимённому ключу. Он создаёт поручение `pending` с каналом `imitation` и запись в `processed_events` в одной транзакции. Повтор с тем же `event_id` подтверждается после завершения транзакции без создания второго поручения.

При ошибке сохранения сервис оставляет сообщение неподтверждённым и повторяет транзакцию с паузой. При потере соединения RabbitMQ может доставить сообщение заново. Невалидный конверт отклоняется без возврата. Настройка DLQ, отложенные повторы по ступеням, отправка уведомлений и публикация исходящих событий относятся к следующим этапам.

На отдельном тестовом стеке с чистой БД и запущенным сервисом проверьте последовательный и одновременный повторы из корня репозитория:

```sh
node --env-file=.env.example services/notifications/scripts/check-subscription-activation.mjs
```

Если стек использует другие адреса, передайте его `RABBITMQ_URL`, `NOTIFICATIONS_DATABASE_URL` и при необходимости `RABBITMQ_MANAGEMENT_URL`. Проверка публикует дважды пример из пакета контрактов, затем одновременно публикует две копии с отдельным `event_id`. Для каждой пары проверяет два подтверждения в брокере, одно поручение и одну запись в `processed_events`.
