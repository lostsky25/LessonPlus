# Границы для следующих изменений

Проект — каркас «Системы учёта абонементов и переносов занятий». Подробности — в `docs/architecture.md`.

## Сохранять

- Пять бизнес-сервисов и gateway остаются раздельными процессами. Сервис не импортирует внутренности другого сервиса и не читает чужую схему.
- Domain не зависит от NestJS, Prisma, RabbitMQ и HTTP DTO. Application зависит от портов, infrastructure их реализует, presentation вызывает сценарии.
- В `@lessonplus/contracts` попадают только внешние DTO и контракты событий. Доменные модели туда не переносятся.
- У каждого сервиса свои Prisma schema, миграции и каталог клиента. Не подключайте бизнес-сервисы суперпользователем PostgreSQL.
- Gateway не получает строку подключения к базам. Браузер не использует имена контейнеров: только `/api` и proxy Vite.
- Повтор события не должен приводить ко второму списанию. Остаток не становится отрицательным. У права одна действующая привязка к записи. Вместимость учитывает подтверждённые записи и действующие резервы. Отмена школой сохраняет право и не тратит лимит пользовательских переносов. Перенос и списание одного права нужно защищать от гонки.

## Объём текущего этапа

Работают структура репозитория, конфигурация, миграции технических таблиц `outbox_events` и `processed_events`, проверка PostgreSQL и RabbitMQ в readiness, Swagger, сбор статусов gateway и стартовый интерфейс.

Не реализованы и не должны имитироваться: CRUD, списание занятий, saga переноса, диспетчер outbox, потребители бизнес-событий, JWT, платежи, CRM и отправка сообщений.
