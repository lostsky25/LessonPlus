# Границы сервисов

Документ описывает пять уже существующих бизнес-сервисов и gateway. Новые сервисы для справочников не вводятся. Пометки: **существует** — есть в репозитории; **проектируется** — решение для следующей реализации, кода ещё нет.

Доменные классы во всех пяти `src/domain` не заведены. В Prisma есть только технические таблицы `outbox_events` и `processed_events`. Команд, которые меняют абонементы, расписание, посещения или переносы, нет. Порты application сейчас ограничиваются проверкой PostgreSQL и RabbitMQ, записью в outbox и учётом обработанного `event_id`.

## Абонементы (`subscriptions`)

**Существует.** Отдельный процесс, схема PostgreSQL `subscriptions`, роль `subscriptions_user`. README сервиса называет его владельцем тарифов, абонементов и прав на занятия.

**Ответственность.** Только этот сервис резервирует, списывает, восстанавливает и перепривязывает право на занятие. Остальные сервисы не меняют остаток и не пишут в его таблицы.

**Собственные сущности, проектируются:**

| Сущность | Что хранит |
| -------- | ---------- |
| Ученик | Справочник учеников и контакт родителя. См. решение о справочниках ниже |
| Тариф | Параметры абонемента. Число занятий, срок и лимит переносов не зафиксированы требованиями |
| Абонемент | Действующий или завершённый договор на тариф для ученика |
| Право на занятие | Единица остатка. У права не больше одной действующей привязки к записи |
| Резерв права | Временное удержание права под запись или перенос. Это не резерв места |

**Принимаемые команды, проектируются:** активировать абонемент, завершить абонемент по его параметрам, зарезервировать право, снять резерв права, списать право, восстановить право, перепривязать право к другой записи. Повтор одной и той же команды или события не списывает право второй раз и не делает остаток отрицательным.

**Внешние зависимости, существуют:** своя база, RabbitMQ, конверт события из `@lessonplus/contracts`. Входящие факты от «Расписания» и «Посещений» проектируются как вызовы API и события, не как чтение чужих схем. Gateway к этой базе не подключается.

## Расписание (`schedule`)

**Существует.** Схема `schedule`, роль `schedule_user`. README называет владельцем группы, занятия, вместимость, записи и резервы мест.

**Ответственность.** Место в группе и факт записи. Сервис не списывает и не восстанавливает право.

**Собственные сущности, проектируются:**

| Сущность | Что хранит |
| -------- | ---------- |
| Преподаватель | Справочник преподавателей, потому что группа и занятие без ведущего не определяются |
| Группа | Состав расписания и привязка к преподавателю |
| Занятие | Конкретное проведение группы, включая вместимость |
| Запись | Подтверждённое место ученика на занятии |
| Резерв места | Удержание места, в том числе под перенос, пока запись не подтверждена или не снята |

Подтверждённые записи и действующие резервы мест вместе не превышают вместимость. Свободное место — этот остаток; чтение числа мест не гарантирует успешную конкурентную запись. Идентификатор ученика и идентификатор права приходят из «Абонементов»; копия справочника учеников здесь не хранится.

**Принимаемые команды, проектируются:** запланировать занятие, отменить занятие школой, подтвердить запись, отменить запись, зарезервировать место под перенос, освободить исходное место переноса. Обычная отмена записи и освобождение старого места при переносе — разные команды: вторая выполняется после новой привязки права и эту привязку не снимает. Отмена школой не проводится как пользовательский перенос и не требует списания права.

**Внешние зависимости, существуют:** своя база и RabbitMQ. Согласование с правом проектируется через API «Абонементов» и события, без общего доступа к таблицам.

## Посещения (`attendance`)

**Существует.** Схема `attendance`, роль `attendance_user`. README ограничивает сервис отметками присутствия и отсутствия.

**Ответственность.** Принять отметку преподавателя, инициировать списание и записать окончательный результат только после подтверждения «Абонементов». Сам сервис остаток не меняет.

**Собственные сущности, проектируются:** отметка посещения или отсутствия по записи. В отметке хранятся идентификаторы занятия, ученика и права, но не сам абонемент и не место в группе.

**Принимаемые команды, проектируются:** запросить регистрацию посещения, зафиксировать посещение после подтверждённого списания, зафиксировать отсутствие. Пока «Абонементы» не подтвердили списание, посещение не считается окончательным.

**Внешние зависимости, существуют:** своя база и RabbitMQ. Запрос списания публикуется событием `AttendanceRegistrationRequested`; получатель — «Абонементы». Ошибка «Уведомлений» эту отметку не отменяет.

## Переносы (`transfers`)

**Существует.** Схема `transfers`, роль `transfers_user`. README прямо говорит, что saga переноса не реализована.

**Ответственность.** Принять заявку, применить параметры правила и координировать «Расписание» и «Абонементы» через API и события. Сервис не владеет ни местом, ни правом: место резервирует «Расписание», право перепривязывает «Абонементы».

**Собственные сущности, проектируются:** заявка на перенос и правило переноса. Срок уведомления и лимит пользовательских переносов — параметры правила и тарифа, не утверждённые числа. Отмена школой в этот лимит не входит.

**Принимаемые команды, проектируются:** запросить перенос, завершить перенос после успешных шагов, отклонить перенос. Использованное право не переносится. Одновременные перенос и списание одного права должны блокировать друг друга; этой защиты в коде нет.

**Внешние зависимости, существуют:** своя база и RabbitMQ. Порядок переноса проектируется в каталоге событий: блокировка исходного права, резерв целевого места, новая привязка, подтверждение новой записи, освобождение исходного места. Алгоритм saga не запускается и здесь не расписывается.

## Уведомления (`notifications`)

**Существует.** Схема `notifications`, роль `notifications_user`. Отправка сообщений не реализована.

**Ответственность.** Принять поручение на уведомление и сохранить результат доставки. `NotificationDeliveryFailed` не отменяет абонемент, запись, посещение или перенос.

**Собственные сущности, проектируются:** уведомление и попытка доставки. Получатель — `studentId` (UUID владельца карточки в «Абонементах»). ФИО и контакт родителя в схему уведомлений не копируют.

**Принимаемые команды, проектируются:** поставить уведомление в доставку, зафиксировать успех, зафиксировать неуспех.

**Внешние зависимости, существуют:** своя база и RabbitMQ. Внешний канал доставки не подключён.

## Gateway и интерфейс

**Существуют.** `api-gateway` не содержит бизнес-правил и не получает строку подключения к базам. Браузер ходит только на `/api`. Разделы интерфейса повторяют пять сервисов и бизнес-данных не показывают.

## Справочники

Отдельный сервис людей, CRM или справочников не создаётся: `AGENTS.md` оставляет CRM за границей этапа, а текущий репозиторий уже состоит из пяти бизнес-сервисов.

| Справочник | Владелец | Почему |
| ---------- | -------- | ------ |
| Ученик и контакт родителя | Абонементы | Абонемент и право существуют до первой записи. Родитель видит остаток и связан с абонементом, а не с конкретным занятием |
| Тариф | Абонементы | Уже назван ответственностью сервиса. Лимиты остаются параметрами |
| Преподаватель | Расписание | Он ведёт группу и занятие. Другому сервису справочник преподавателей не нужен |
| Группа | Расписание | Это часть расписания, а не абонемента |
| Правило переноса | Переносы | Координатор применяет правило, не владея правом и местом |
| Канал уведомления | Уведомления | Доставка не должна жить в бизнес-операции |

«Расписание», «Посещения», «Переносы» и «Уведомления» хранят идентификатор ученика. Второй справочник учеников у них не появляется.

Таблицы источника истины, чтения и проекций — в [storage/01-data-ownership.md](storage/01-data-ownership.md).

## Единственный владелец

| Сущность | Владелец |
| -------- | -------- |
| Ученик, контакт родителя, тариф, абонемент, право, резерв права | Абонементы |
| Преподаватель, группа, занятие, запись, резерв места | Расписание |
| Отметка посещения или отсутствия | Посещения |
| Заявка и правило переноса | Переносы |
| Уведомление и результат доставки | Уведомления |

Gateway, контракты и пакет конфигурации сущностей не владеют.
