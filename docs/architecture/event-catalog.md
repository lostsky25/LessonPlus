# Каталог событий

Имена взяты из `packages/contracts/src/events.ts`. Расхождения с согласованным списком нет: в каталоге те же 20 имён, без переименований и без дополнительных бизнес-событий.

**Существует:** тип конверта `EventEnvelope` с полями `event_id`, `event_type`, `schema_version`, `occurred_at`, `correlation_id`, `payload`. Идентификатор — UUID, время — ISO 8601. Имя события проверяет `isEventName`. Поля `payload` намеренно не заданы.

**Существует:** в каждом сервисе таблицы `outbox_events` и `processed_events` и порты `OutboxEventStore` и `ProcessedEventStore`.

**Не существует:** публикация этих 20 событий, диспетчер outbox, потребители и saga. Получатели ниже — проектируемая связь, а не работающий код.

Ошибка доставки (`NotificationDeliveryFailed`) никого не просит откатывать бизнес-операцию.

## Абонементы публикуют

| Событие | Проектируемые получатели | Смысл |
| ------- | ------------------------ | ----- |
| `SubscriptionActivated` | Уведомления | Абонемент стал действующим |
| `SubscriptionExpired` | Уведомления, Переносы | Абонемент завершён; новую заявку на его права принимать нельзя |
| `LessonRightReserved` | Переносы | Блокировка неиспользованного права. В переносе это первый шаг; «Расписание» получателем блокировки права не является. До новой привязки блокировку можно снять |
| `LessonRightReleased` | Переносы | Снятие блокировки права при компенсации до фиксации новой привязки |
| `LessonRightConsumed` | Посещения, Уведомления | Списание подтверждено. Посещения после этого фиксируют окончательный результат |
| `LessonRightRestored` | Посещения, Уведомления | Списанное право возвращено в остаток |
| `LessonRightTransferred` | Переносы, Расписание | Новая привязка права зафиксирована. После этого перенос доводят до конца, а целевой резерв места не истекает. Уведомление об итоге идёт отдельным событием заявки |

Только «Абонементы» выпускают события резерва, списания, восстановления и перепривязки права.

## Расписание публикует

| Событие | Проектируемые получатели | Смысл |
| ------- | ------------------------ | ----- |
| `LessonScheduled` | Уведомления | Занятие поставлено в расписание |
| `LessonCanceledBySchool` | Абонементы, Переносы, Посещения, Уведомления | Занятие отменено школой. Абонементы сохраняют право. Переносы не расходуют лимит пользователя |
| `BookingConfirmed` | Переносы; вне переноса также Абонементы и Уведомления | Запись подтверждена. В переносе это шаг после `LessonRightTransferred`: привязку событие не создаёт, координатор — «Переносы». Вне переноса «Абонементы» связывают право с этой записью |
| `BookingCanceled` | Вне переноса — Абонементы и Уведомления. Освобождение исходного места переноса — Переносы | Обычная отмена снимает привязку права, только если она ещё указывает на эту запись. `BookingCanceled` исходной записи после новой привязки освобождает старое место и новую привязку не снимает |
| `TransferSeatReserved` | Переносы | Место под перенос удержано |

## Посещения публикуют

| Событие | Проектируемые получатели | Смысл |
| ------- | ------------------------ | ----- |
| `AttendanceRegistrationRequested` | Абонементы | Запрос списания. Это инициация, ещё не окончательная отметка |
| `AttendanceRecorded` | Уведомления | Окончательное посещение после `LessonRightConsumed` |
| `AbsenceRecorded` | Уведомления | Окончательное отсутствие. Правило списания для отсутствия не задано |

## Переносы публикуют

| Событие | Проектируемые получатели | Смысл |
| ------- | ------------------------ | ----- |
| `TransferRequested` | Расписание, Абонементы, Уведомления | Заявка принята координатором и ещё не выполнена |
| `TransferCompleted` | Уведомления | Заявка завершена после новой привязки, подтверждения новой записи и освобождения исходного места |
| `TransferRejected` | Уведомления | Заявка отклонена до фиксации новой привязки. Новая привязка ещё не создана, исходное право остаётся неиспользованным |

## Уведомления публикуют

| Событие | Проектируемые получатели | Смысл |
| ------- | ------------------------ | ----- |
| `NotificationDelivered` | Нет бизнес-получателя | Доставка успешна |
| `NotificationDeliveryFailed` | Нет бизнес-получателя | Доставка не удалась и не отменяет исходную операцию |

## Согласованный поток

Проектируется, не реализовано.

1. Посещение: «Посещения» публикуют `AttendanceRegistrationRequested`. «Абонементы» списывают право и публикуют `LessonRightConsumed`. Только затем «Посещения» публикуют `AttendanceRecorded`.
2. Перенос, только как проект и без алгоритма. Порядок: блокировка исходного неиспользованного права (`LessonRightReserved`) → резерв целевого места (`TransferSeatReserved`) → фиксация новой привязки (`LessonRightTransferred`) → подтверждение новой записи (`BookingConfirmed`) → освобождение исходного места (`BookingCanceled` исходной записи) → `TransferCompleted`. До фиксации новой привязки допустимы компенсации: снять целевой резерв, снять блокировку права и опубликовать `TransferRejected`. После фиксации операцию доводят до конца, целевой резерв от истечения защищён. Освобождение исходного места не является обычной отменой и не снимает новую привязку.
3. Отмена школой: источник — `LessonCanceledBySchool` у «Расписания». Дальше право сохраняется, пользовательский лимит переносов не тратится.

Повтор события с тем же `event_id` проектируется как уже обработанный через `processed_events`. Сейчас потребитель, который это делает, не запущен.

## Проверка списка

В документе и в `eventCatalog` по двадцать имён, по одному разу:

`SubscriptionActivated`, `SubscriptionExpired`, `LessonRightReserved`, `LessonRightReleased`, `LessonRightConsumed`, `LessonRightRestored`, `LessonRightTransferred`, `LessonScheduled`, `LessonCanceledBySchool`, `BookingConfirmed`, `BookingCanceled`, `TransferSeatReserved`, `AttendanceRegistrationRequested`, `AttendanceRecorded`, `AbsenceRecorded`, `TransferRequested`, `TransferCompleted`, `TransferRejected`, `NotificationDelivered`, `NotificationDeliveryFailed`.
