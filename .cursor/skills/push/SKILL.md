# /push

Явный вызов `/push` уже разрешает commit и push. Повторно не спрашивай подтверждение. Соблюдай разрешения инструментов Cursor. Целевой репозиторий: `git@github.com:lostsky25/LessonPlus.git`.

Не используй force push, `--force-with-lease`, `reset --hard`, `commit --amend`, rebase и прочие переписывания истории. Не меняй `git config`, не пропускай hooks и не придумывай `user.name` или `user.email`. Сообщение commit передавай в Git массивом аргументов, без подстановки в строку shell. На Windows вызывай `pnpm` так, чтобы запустился `pnpm.cmd`, и не помещай текст пользователя в shell-строку.

## Шаги

1. Из корня репозитория посмотри `git status`, текущую ветку и remotes. Адреса remote читай через `git config --get-regexp`, а не через отображаемый URL после rewrite. При detached HEAD остановись. При незавершённых merge, rebase или конфликтах остановись и объясни причину; не разрешай конфликт угадыванием.

2. Выбери remote целевого репозитория. Сравнивай URL без учёта регистра и суффикса `.git`. Если `origin` указывает на целевой репозиторий, используй его. Если указывает на другой, сохрани `origin`. Затем используй remote `lessonplus`, когда он уже указывает на цель. Если такого remote нет, добавь `lessonplus` с URL `git@github.com:lostsky25/LessonPlus.git`. Если имя `lessonplus` занято другим адресом, остановись и напиши оба адреса. Если `origin` отсутствует, добавь его с целевым URL.

3. Выполни из корня, по порядку: `pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm test`. `pnpm test` запускает Jest; на текущем этапе тестов бизнес-логики нет, и успешное завершение без проверок допустимо. Не пиши тесты ради пустых классов. Если ошибка относится к текущим изменениям и её можно исправить в границах `AGENTS.md`, исправь и повтори упавший шаг и следующие. При нерешённой ошибке остановись до `git add`, commit и push.

4. Добавь изменения проекта в индекс из корня. Проверь `git diff --cached --name-only` и сам diff, включая уже отслеживаемые файлы, которые `.gitignore` не защищает. В commit не должны попасть `.env` и `.env.*` (кроме `.env.example` с учебными значениями), `node_modules`, `dist`, `coverage`, `src/generated`, приватные ключи, `credentials.json` и реальные токены или пароли. Обнаруженный секрет сними с индекса, не удаляя рабочую копию, и остановись. `.env.example` допустим.

5. Если после добавления индекс пуст, не создавай пустой commit. Если изменения есть, проверь, что `user.name` и `user.email` уже заданы; иначе остановись и попроси настроить их самостоятельно. Создай обычный commit. Текст после `/push` бери как сообщение целиком, без префикса команды. Если текста нет, составь сообщение по фактическому diff в формате Conventional Commits: `feat`, `fix`, `docs`, `refactor` или `chore`, при необходимости со scope. Не используй шаблон `chore: update LessonPlus`, когда по diff видно конкретное изменение.

6. Отправь текущую ветку обычным push именно в выбранный remote. Если upstream отсутствует, первая отправка — `git push --set-upstream <remote> HEAD`. Если upstream уже указывает на другой remote, не меняй его: вызывай `git push <remote> <ветка>` без `--set-upstream`. При non-fast-forward, отказе сервера, защите ветки или ошибке SSH остановись и процитируй причину из вывода Git. Не подтягивай историю rebase-ом и не перезаписывай её.

7. Сообщи ветку, полный хеш commit и фактический результат отправки: имя remote, создана ли ветка на сервере, `Everything up-to-date` или текст отказа. Если commit не создавался, явно напиши, что пустой commit пропущен, и покажи хеш отправленного существующего commit.
